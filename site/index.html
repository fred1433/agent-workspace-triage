## Not measured in this run

- Agent sessions: not inventoried. The optional inventory lists processes with their age, terminal and working directory, and reports progress as unknown, because no progress source exists on the filesystem.
- Hook rejection rate: no hook log was given, so no rate is computed. A rate needs the calls examined over a period, the reasons kept apart, and retries counted as retries.
- node_modules sizes: counted, not weighed. Sizes are an option because weighing them walks every file, which is the walk that times out on a workspace this size.

## Boundaries

- the collector calls no external service and sends no report
- no file, index, reference or configuration of an inspected repository is written; git is called with --no-optional-locks
- no cleanup command is printed or executed; a status is a proposal with its evidence
- nothing outside the roots you name is read, including the owner of a worktree attached elsewhere

On your own roots, it is one file and no dependencies:

python3 triage.py --root ~/code --root ~/work --markdown triage.md

What it does not claim

The boundaries are part of the work. Each one is a test in the repository, not a sentence on a page.

  • It does not detect a hung session. The optional inventory lists the agent processes that exist, with age, terminal and working directory, and reports progress as unknown. A process name and an age describe a process, not the progress of the work it was given.
  • It does not compute a rejection rate out of a log of refusals. A rate needs the calls examined over a period, the reasons kept apart and retries counted as retries. Without that denominator it says so instead of producing a number.
  • It reads nothing outside the roots you name, writes nothing at all, and prints no command to paste. Read only is checked by fingerprinting every file, index, reference and configuration before and after the run, and every git call carries --no-optional-locks, since a plain status can otherwise refresh and write the index.
  • An interrupted walk is reported as partial, never as nothing found and never as clean. There is a time budget per root, a depth limit and explicit exclusions, because the symptom that starts all of this is a search that walks everything and times out.
