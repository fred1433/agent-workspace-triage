## Boundaries

- no external service is called and no report is sent: the collector imports no network client, and a control runs a whole collection with no network access at all
- nothing under the roots you name is written: no file, no index, no reference, no configuration. Git is called with --no-optional-locks, and a repository that configures a content filter is left uninspected rather than have git run that filter. The report is written where you ask for it, and nowhere else
- no cleanup command is printed or executed; a status is a proposal with its evidence
- nothing outside the roots you name is read, including the owner of a worktree attached elsewhere, which is not asked anything at all

Fixture convention: 131 candidate directories, including 41 unregistered. Illustrative hypothesis, not a reconstruction. The choice, and every situation built into the workspace, is written in fixture/MANIFEST.md.

On your own roots, it is one file and no dependencies. It reads the roots and writes one file, triage.md, where you ask for it:

python3 triage.py --root ~/code --root ~/work --markdown triage.md

What it does not claim

The boundaries are part of the work. Each one is a test in the repository, not a sentence on a page.

  • It does not detect a hung session. The optional inventory lists the agent processes that exist, with age, terminal and working directory, and reports progress as unknown. A process name and an age describe a process, not the progress of the work it was given.
  • It does not compute a rejection rate out of a log of refusals. A rate needs a log that says it records every call examined, over a period, with an identifier per attempt. Without that, it says so instead of producing a number.
  • It leaves the inspected data unchanged, and the only thing it writes is the report, where you ask for it. That is checked by fingerprinting every file, index, reference and configuration before and after the run. Every git call carries --no-optional-locks, since a plain status can otherwise refresh and write the index, and a repository that configures a content filter is left uninspected rather than have git run somebody else's conversion command on our behalf.
  • It reads nothing outside the roots you name, not even the default branch of a repository that owns a worktree from elsewhere, and prints no command to paste. A test records the directory of every command that ran.
  • It calls no external service and sends no report. A control runs the whole collection inside a network namespace with nothing in it, and the report still comes out whole.
  • A walk that stops early is reported as partial, and a walk that stops inside its own limits is reported as bounded, with a count of what was left unopened. Neither is ever read as nothing found, and neither is read as clean.
